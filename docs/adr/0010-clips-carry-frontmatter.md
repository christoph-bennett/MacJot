# Clips carry frontmatter

A Note created from a selection in another app (a Clip) is written with YAML frontmatter holding `created` (local time with offset), `source` (the app) and `page` (the front window's title with the app's name and browser profile removed, left out for Terminal and iTerm) and `url` (the page's address, only when the app puts it on the pasteboard with the copy, as Chrome and Edge do under `org.chromium.source-url`; decided 2026-11-15); values that are unknown are left out (MacJot takes only what the Accessibility API and the pasteboard give it: no AppleScript or System Events, which would need a further Automation permission per app, so Safari Clips have no `url`; `org.nspasteboard.source`, where a copy carries it, names the `source` when the frontmost app isn't known, as for a Clip from the clipboard), and a Clip from the clipboard or the Service has neither `source` nor `page`. Ordinary Notes still get none, so this reverses spec 0001 story 43 ("write no frontmatter") for Clips only; existing frontmatter is still preserved verbatim and skipped when deriving the Title. The key names match the app Jot, which Christoph tested beside MacJot, so its Clips stay readable in both; we left out its `id`, `done`, `pin`, `archived`, `section`, `tags` and `images`, because MacJot has no such features. The Frontmatter Section shows the block collapsed by default in every Note that has one, so the YAML doesn't get in the way of reading.
