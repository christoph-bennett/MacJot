# The Date Prefix is whatever precedes the Title's name

The Date Prefix is written in a configurable Date Prefix Format, built freely from year, month, day and separator elements with no required parts (decided 2026-10-11; amends ADR 0003's fixed `yyyy-mm-dd-`). MacJot never parses a date out of a prefix. To keep the prefix when a Note is renamed after its Title changes, it takes everything in the filename before the Title's own name (its slug, or slug-`N`) as the prefix, whichever format wrote it: `20261011_plan.md` with the Title "Plan" keeps `20261011_`. Only when the filename doesn't end with the Title's name (the Title was changed by another app) does MacJot fall back to recognising a prefix in the current or the default format. We chose this over remembering every format ever used and parsing prefixes with all of them, because formats can include localised month names, may lack the day or the year, and can change any time; the date such parsing would yield was shown nowhere (the Note List sorts and dates by modification), so the creation date derived from the prefix was removed with it. The cost: a Note whose Title was changed outside MacJot, with a prefix in a format no longer current, loses that prefix when it's renamed.
