# Spec 0001 — Jot MVP

Status: ready-for-agent

Vocabulary follows [GLOSSARY.md](../../GLOSSARY.md). Respects [ADR 0001](../adr/0001-markdown-files-are-source-of-truth.md), [ADR 0002](../adr/0002-native-appkit.md), [ADR 0003](../adr/0003-filenames-follow-title.md).

## Problem Statement

I want to capture a thought the instant I have it, without switching apps, picking a location or naming a file, and I want what I write to end up as plain Markdown files I own and can open with any tool. Existing apps either hide notes in a proprietary database, are slow to summon, or carry far more features (AI, sync, stats) than I need. People who don't know Markdown syntax also need a way to format without learning it.

## Solution

Jot is a menu-bar-only macOS app. A Capture Hotkey summons a floating Capture Panel with a fresh Draft, ready to type; a Search Hotkey summons the same panel with the Note List and search focused. Every Note is a `.md` file in one user-chosen Notes Folder, named after its Title. The editor shows styled Markdown (syntax visible but dimmed) and a Formatting Toolbar applies or removes formatting for users who don't type syntax. Saving is automatic and invisible; there is no save step and no empty file clutter.

## User Stories

### Summoning & panel

1. As a user, I want to press a global Capture Hotkey from any app, so that I can start writing a Note without switching context.
2. As a user, I want the Capture Panel to open with the cursor already in a new Draft, so that I can type immediately.
3. As a user, I want a separate Search Hotkey, so that I can find a Note without first creating a Draft.
4. As a user, I want the Search Hotkey to open the Note List with the search field focused, so that I can type my query immediately.
5. As a user, I want pressing the same hotkey again while the panel is focused to hide it, so that the hotkey acts as a toggle.
6. As a user, I want pressing a hotkey while the panel is visible but not focused to bring it to the front without discarding what it shows, so that I don't lose my place.
7. As a user, I want pressing the other hotkey while the panel is focused to switch modes, so that I can jump between writing and searching.
8. As a user, I want to configure both hotkeys in Settings, so that they don't clash with my other tools.
9. As a user, I want to be told when a hotkey I choose is unavailable, so that I'm not left with a silently dead shortcut.
10. As a user, I want the hotkeys to work without granting Accessibility permission, so that setup is frictionless.
11. As a user, I want the Capture Panel to float above my other windows and appear on my current Space, so that I never have to look for it.
12. As a user, I want the panel to remember its size and position, so that it opens where I like it.
13. As a user, I want the panel to fall back to the centre of my current screen when its remembered screen is disconnected, so that it never opens off-screen.
14. As a user, I want a single Settings button that resets the panel's size and position, so that I can recover from a bad layout.
15. As a user, I want `Esc` to clear a non-empty search and otherwise close the panel, so that I can dismiss it from the keyboard.
16. As a user, I want the panel to hide when it loses focus while showing only an untouched Draft, so that an accidental summon doesn't linger.
17. As a user, I want `⌘N` to start a new Draft from anywhere in the panel, so that I can capture a second thought quickly.
18. As a user, I want to collapse and expand the Note List with `⌃⌘S` (Apple's "Show Sidebar"; `⌘\` needs four keys on a German layout), so that I can give the editor full width.

### Menu bar & system

19. As a user, I want Jot to live only in the menu bar with no Dock icon, so that it stays out of my way.
20. As a user, I want the menu-bar menu to offer New Note, Show Notes, Settings… and Quit, so that I can reach everything with the mouse too.
21. As a user, I want Jot to launch at login by default, with a toggle in Settings, so that the hotkeys are always available.
22. As a first-time user, I want Jot to create a default Notes Folder and show a brief hint with both hotkeys, so that I can start without an onboarding flow.

### Drafts, saving & lifecycle

23. As a user, I want a Draft to create no file until I type something, so that my Notes Folder isn't littered with empty files.
23a. As a user, I want a Note's file to appear only once I've finished its Title line (pressed Return after it) or left the Note, so that its filename reflects the whole Title rather than the first few words I typed.
23b. As a user, I want what I type before the Title is finished to be kept in a Recovery Copy and restored as a Note after a crash, so that waiting for the Title never risks losing text.
24. As a user, I want my Note saved automatically shortly after I stop typing, so that I never lose work.
25. As a user, I want my Note saved when I close the panel, switch Notes or quit, so that closing is always safe.
26. As a user, I want closing never to ask me to save, so that dismissing is instant.
27. As a user, I want a Note I've emptied to be moved to the system Trash when I leave it, so that blank files don't pile up and I can still recover it.
28. As a user, I want Jot to remember my cursor position in each Note, so that I can resume where I left off.
29. As a user, I want text typed while a save is in progress to be persisted too, so that fast typing is never lost.
30. As a user, I want files written atomically, so that a crash never leaves a half-written Note.

### Titles & filenames

31. As a user, I want the first non-blank line of a Note to be its Title even if it isn't a heading, so that I don't have to think about naming.
32. ~~As a user, I want the Title line visually emphasised in the editor.~~ Dropped after trying it: a first line looking like a heading without `#` was confusing. The Title still names the file; only `#` makes a heading.
33. As a user, I want each Note's filename to be a readable slug of its Title, so that I can browse Notes in Finder and other Markdown tools.
34. As a user, I want accented characters transliterated to plain letters in filenames (e.g. "Über" → "uber"), so that filenames stay ASCII but readable.
35. As a user, I want leading Markdown syntax ignored when deriving the filename, so that "# Plan" and "- [ ] Plan" both become "plan".
36. As a user, I want a Title with no usable characters to produce "untitled", so that every Note still gets a valid filename.
37. As a user, I want clashing filenames to get a numeric suffix, so that no Note ever overwrites another.
38. As a user, I want overly long Titles shortened at a word boundary, so that filenames stay manageable.
39. As a user, I want the file renamed when I change the Title and leave the Note, not while I type, so that other tools and sync don't see constant churn.
40. As a user, I want an optional Date Prefix (creation day) on new Notes' filenames, so that Notes sort chronologically in Finder.
41. As a user, I want the Date Prefix preserved when a Note is renamed, so that it always records the creation day.
42. As a user, I want toggling the Date Prefix to affect only new Notes, so that my existing files aren't mass-renamed.
43. As a user, I want Jot to write no frontmatter, and to preserve any frontmatter already in a file, so that my files stay clean and compatible.

### Editor & Formatting Toolbar

44. As a user, I want Markdown rendered as styled text with the syntax dimmed but visible, so that what I see is exactly what's stored.
45. As a user, I want proportional system type for prose and monospace for code and syntax markers, so that notes read well.
46. As a user, I want to set the editor font size, so that it's comfortable to read.
46a. As a user, I want line numbers next to the editor's lines, on by default and switchable off in Settings, so that I can refer to and find lines easily.
47. As a user unfamiliar with Markdown, I want toolbar controls for bold, italic and strikethrough, so that I can format without knowing syntax.
48. As a user, I want a heading control offering H1, H2, H3 and plain text, so that I can structure a Note.
49. As a user, I want toolbar controls for bullet, numbered and checklist lists, so that I can make lists easily.
50. As a user, I want toolbar controls for quote, inline code and link, so that I can mark those up easily.
51. As a user, I want each formatting control to remove formatting that's already applied, so that I can undo formatting the same way I applied it.
52. As a user, I want applying a heading to a list item or quote to replace its line prefix rather than stack markers, so that the result is valid Markdown.
53. As a keyboard user, I want shortcuts for bold, italic, strikethrough and headings, so that I don't need the mouse.
53a. As a user, I want Return to start a new paragraph (a blank line in the file) and Shift-Return to insert a single line break, so that my lines show up separately in every Markdown viewer, not just in Jot.
54. As a user, I want Return in a list item to continue the list (incrementing numbers, unchecked boxes), so that writing lists is fluid.
55. As a user, I want Return on an empty list item to end the list, so that I can get out of a list naturally.
56. As a user, I want to tick checklist boxes by clicking them, so that I can use Notes as to-do lists.

### Note List & search

57. As a user, I want the Note List sorted by last modification, newest first, so that recent Notes are at hand.
58. As a user, I want each row to show Title, date and a one-line preview, so that I can recognise Notes at a glance.
59. As a user, I want to choose between relative dates and absolute dates in my system's short format, so that dates read the way I prefer.
60. As a user, I want search to filter Notes live by Title and body, ignoring case and diacritics, so that I find Notes as I type.
61. As a user, I want the preview to show the matching snippet while searching, so that I can see why a Note matched.
62. As a user, I want to move through results with the arrow keys and open one with Return, so that searching is keyboard-only.
63. As a user, I want to reveal a Note in Finder, open it in my default Markdown app, copy it as Markdown, or move it to the Trash from a context menu or the editor's `⋯` menu, so that I can act on it outside Jot.
64. As a user, I want deleting a Note (Delete/Forward Delete/⌘⌫ in the Note List, context menu, `⋯`) to ask for confirmation and then move it to the system Trash, so that I don't delete by accident and can still recover it.
64a. As a user, I want a Settings option to turn that confirmation off (on by default), so that deleting can be fast once I'm used to it.

### Folder & external changes

65. As a user, I want to choose my Notes Folder in Settings, so that Notes can live in iCloud Drive, an Obsidian vault or anywhere I like.
66. As a user, I want to be told, when I change the Notes Folder, that existing Notes must be moved manually, with a button to show the old folder, so that I'm not surprised by an empty list.
67. As a user, I want Notes I add, edit, rename or delete with other tools to be reflected in the Note List, so that Jot never shows stale data.
68. As a user, I want the open Note to reload silently when it changes on disk and I have no unsaved edits, so that I see the latest version.
69. As a user, I want my unsaved edits to win when the open Note also changed on disk, so that I never lose what I just typed.
70. As a user, I want Jot to follow system light/dark appearance, so that it fits my desktop.

## Implementation Decisions

- **Stack:** Swift, AppKit-first; SwiftUI only for secondary views (Settings) hosted in AppKit. macOS 14+. Menu-bar agent app (no Dock icon). Unsandboxed, Developer-ID distributable; avoid choices that block a later sandboxed build. Bundle ID `com.onethingwell.jot` (working title).
- **Module split:** a pure-Swift core module with no AppKit dependency, and a thin AppKit app shell. All domain logic lives in the core; the shell only wires UI events to the core and renders its state.
- **Core module: Notes Folder** — the single facade the app uses for everything Note-related. Responsibilities:
  - Draft lifecycle: begin a Draft, update its text, leave it. A Draft materialises as a file in the Notes Folder when its Title is finished (a line break follows the first non-blank line) or when it is left with content; until then flushes write the Recovery Copy (one file in an app-private location outside the Notes Folder) instead. Materialising deletes the Recovery Copy. At construction, an existing Recovery Copy with content is materialised as a Note (crash recovery). Leaving an emptied Note trashes it.
  - Saving: accepts text updates; persistence is triggered by explicit "flush" calls the shell makes on a debounce timer and on leave/close/quit. Writes are atomic and serialised per Note, and a flush loops until the persisted text equals the latest text.
  - Naming: derives the filename from the Title (strip leading Markdown → transliterate to ASCII → lowercase → non-alphanumerics to `-` → collapse/trim → cap 60 chars at a word boundary → `untitled` fallback → `-N` collision suffix). Optional Date Prefix applied at creation from an injected clock, preserved on rename. Rename happens only on leave.
  - Note List state: list of Notes (identity, Title, modified date, preview), sorted by modified date; search returning matches with snippets; case- and diacritic-insensitive substring matching held in memory.
  - External changes: consumes file-system change events for the folder; updates the Note List; for the open Note, reloads if clean, keeps local text if dirty.
  - Created date: none (decided 2026-10-11, ADR 0009): the Date Prefix is never parsed back into a date; it's found as whatever precedes the Title's name in the filename.
  - Dependencies injected at construction: folder location, Recovery Copy location, clock, trash operation, file-system event source. No other collaborators.
  - Frontmatter: never written; if present it is preserved verbatim and excluded from Title derivation.
- **Core module: Editing commands** — pure functions over (text, selection) → (text, selection): toggle bold/italic/strikethrough/inline code/link, set heading level (replacing existing line prefixes), toggle bullet/numbered/checklist/quote, Return outside lists/quotes/frontmatter inserting a paragraph break (`\n\n`, single `\n` on an already blank line), Shift-Return inserting a single `\n`, list continuation on Return (and termination on empty item), checkbox toggle at a position, Title-line detection (for styling).
- **App shell:**
  - Status item with menu (New Note, Show Notes, Settings…, Quit); launch-at-login via the system login-item service, on by default.
  - Two global hotkeys registered via the Carbon hot-key API (no Accessibility permission), reconfigurable; registration failure surfaced in Settings.
  - Floating panel; size and position persisted; off-screen fallback to centre of the current screen; Settings reset button.
  - Hotkey state matrix:

    | Panel state | Capture Hotkey | Search Hotkey |
    |---|---|---|
    | Hidden | Show panel with a new Draft | Show panel, Note List open, search focused |
    | Visible, not key | Bring to front, keep content | Bring to front, focus search |
    | Key, same mode | Hide | Hide |
    | Key, other mode | Switch to new Draft | Switch to search |
  - Text editor on TextKit with Markdown styling (dimmed syntax, SF Pro prose / SF Mono code and markers), clickable checkboxes, and toolbar/shortcut actions delegating to Editing commands.
  - Note List sidebar bound to Notes Folder state; relative/absolute date formatting per setting; context actions (Reveal in Finder, Open in Default App, Copy as Markdown, Move to Trash).
  - Settings: Notes Folder (with "move manually" dialog + Show Old Folder), both hotkeys, launch at login, font size, Date Prefix, relative dates, reset panel. Per-Note cursor positions and panel geometry are app preferences, never written into Notes.
  - File-system watching via FSEvents, feeding events into Notes Folder.
- **Line numbers:** a gutter left of the editor numbering the file's lines (not wrapped visual lines), in small dimmed SF Mono; setting on by default.
- **Default values:** Capture Hotkey `⌃⌥N`; Search Hotkey `⌃⌥F`; Notes Folder `~/Documents/Jot/`; Date Prefix off; relative dates on; launch at login on; autosave debounce ~0.5 s.
- **Search Index:** in-memory for the MVP. A future SQLite FTS5 index must remain fully derivable from the files (ADR 0001).

## Testing Decisions

- **Good tests** exercise external behaviour only: given inputs at a seam, assert observable outputs (files on disk, returned Note List state, returned text and selection). No assertions on private state, call order or internal helpers. Tests should survive refactors of the internals.
- **Seam 1 — Notes Folder** (primary seam): tests construct it over a real temporary directory with an injected clock, a recording trash, and a manually driven file-system event source. They assert on the directory contents and the Note List state. Covers Draft lifecycle, flush semantics, Title-finished materialisation and the Recovery Copy (written before materialisation, deleted after, restored at construction), all filename rules (slug cases are asserted as resulting filenames, not via a standalone slug function), Date Prefix creation and preservation, rename-on-leave, collisions, trashing emptied Notes, frontmatter preservation, sorting, search and snippets, external add/edit/rename/delete, clean-reload vs dirty-wins. Filename cases that must pass:
  - `# Über Änderungen!` → `uber-anderungen.md`
  - `- [ ] Call Anna` → `call-anna.md`
  - `🎉🎉` → `untitled.md`
  - Two Notes titled `Meeting` → `meeting.md`, `meeting-2.md`
  - Title preceded by blank lines → slug of the first non-blank line
  - Date Prefix on, created 2026-10-08, later retitled → `2026-10-08-<new-slug>.md`
  - Date Prefix switched on after a Note exists → existing filename unchanged
- **Seam 2 — Editing commands:** table-driven tests of (text, selection) in → (text, selection) out. Covers every toggle being its own inverse, paragraph breaks on Return vs single breaks on Shift-Return / blank lines / lists / quotes / frontmatter, heading prefix replacement, list continuation/termination including numbering, checkbox toggling, Title detection with leading blank lines.
- **Not automated:** the AppKit shell (panel, hotkeys, status item, Settings, styling) is verified manually against the hotkey state matrix and this checklist:
  - App never appears in the Dock or ⌘-Tab.
  - Toggling launch at login takes effect without restart.
  - Both hotkeys work from any app, including full-screen apps.
  - Changing a hotkey re-registers immediately; an unavailable combination is reported.
  - Panel restores size and position; with its screen disconnected it centres on the current screen; the reset button restores defaults.
  - `Esc` clears search, then closes; blur with an untouched Draft hides the panel. If the hotkey/panel logic grows, extract it into a pure state machine as a third seam rather than UI-testing it.
- **Prior art:** none — greenfield repository. Use XCTest (or Swift Testing) in the core package; these tests become the reference pattern.

## Further Notes

- Build order (each milestone ends in something runnable):
  1. **Skeleton**: Xcode project with the core package, menu-bar agent, status item and menu, Settings window shell, launch at login.
  2. **Hotkeys & panel**: both hotkeys, panel behaviour, state matrix, size/position memory.
  3. **Files**: Notes Folder, naming, Draft lifecycle, autosave, rename-on-leave, Trash (Seam 1 tests).
  4. **Editor styling**: Markdown styling, list continuation, clickable checkboxes.
  5. **Formatting Toolbar**: editing commands and shortcuts (Seam 2 tests).
  6. **Note List & search**: sidebar, search, keyboard navigation, context actions.
  7. **Watching**: FSEvents reconciliation.
  8. **Settings & first launch**: remaining settings, folder-change dialog, first-run hint.

- Reference app: Stik (github.com/0xMassi/stik_app, Tauri/React/CodeMirror). Borrowed ideas: empty capture is a no-op, hide-on-blur when empty, flush-until-equal save loop, atomic writes, in-memory search with watcher, no frontmatter. Deliberate divergence: Title-slug filenames renamed on leave (ADR 0003) instead of immutable timestamp names; autosave while typing with a Recovery Copy until the Title is finished, where Stik saves the capture only on close (losing it on a crash); system Trash instead of an app-managed trash folder.
- "Jot" and `com.onethingwell.jot` are working names; change the bundle ID before the first public release, since it can't change afterwards without losing user settings and permissions.
- Issue tracker not yet configured; this spec lives in the repo until one is set up.
